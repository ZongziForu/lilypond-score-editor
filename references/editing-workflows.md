# Editing Workflows

## Create score workflow

1. Infer instrumentation, key, time, pickup, lyrics, chords, MIDI needs.
2. **Check instrument ranges** (see `references/instrument-ranges-and-pitfalls.md`) before writing notes — LilyPond will engrave unplayable notes without complaint.
3. Choose a template from `${CLAUDE_SKILL_DIR}/assets/templates`.
4. Copy the template into the project.
5. Edit `\header`, key, time, and global block.
6. Fill music variables.
7. Compile and fix errors.

## Edit existing score workflow

1. Inspect structure: `\version`, variables, contexts, includes.
2. Identify the target voice, staff, or measure.
3. Make a minimal, focused edit.
4. Compile.
5. Parse log and repair if needed.
6. Show a relevant git diff.

## Debug workflow

1. Run compile.
2. Parse log with `parse_lilypond_log.py`.
3. Note line/column numbers.
4. Inspect surrounding braces and music expressions.
5. Repair incrementally (one issue at a time).
6. Recompile and confirm.
7. **Regenerate PDF + MIDI** after every change — never leave stale outputs.

## Transposition workflow

1. Distinguish concert pitch vs. written pitch.
2. Prefer `\transpose` over manual pitch rewrites.
3. Keep source variables in concert pitch when possible.
4. Be aware of enharmonic spelling risks.
5. Example:
   ```lilypond
   \transpose c d { \clarinetMusic }
   ```

## Part extraction workflow

1. Identify staves and their music variables.
2. Prefer manifest + wrapper generation.
3. Run `extract_parts.py`.
4. Generate one output per part.
5. Preserve shared global settings.
6. If the source has no separate variables, refactor into variables first.

## Lyrics workflow

1. Use `\lyricmode` for lyric text.
2. Use `\lyricsto` to attach to a named voice.
3. Handle melisma with `__`.
4. Handle syllables with `--`.
5. Check compiler warnings about lyric alignment.

## Chord names workflow

1. Use `\chordmode` for harmonic content.
2. Place in a `\new ChordNames` context.
3. Combine with melody and lyrics for lead sheets.

## Layout workflow

1. Use `\paper` for page-level settings (size, margins, page breaks).
2. Use `\layout` for engraving and context settings.
3. Use line/page breaks sparingly.
4. Use `\once \override` for local tweaks.
5. Avoid global overrides unless specifically requested.

## Import cleanup workflow

After `musicxml2ly`, `midi2ly`, or `abc2ly`, expect to clean:

- Voices and polyphony
- Rhythm spelling and redundant tuplets
- Enharmonics
- Repeats and alternatives
- Ties and beams
- Lyrics alignment
- Layout and spacing
- Variable names
- Redundant generated boilerplate

## Batch transposition workflow

For transposing multiple instruments or generating a score in a new key:

1. Keep the source variables in concert pitch.
2. Use `\transpose` inside each staff or part wrapper for the target instrument.
3. For a full-score key change, apply `\transpose` at the `\score` level or regenerate wrappers.
4. Example: generate Bb clarinet parts from concert-pitch source:
   ```lilypond
   \new Staff \with { instrumentName = "Clarinet in Bb" }
   \transpose bes c' { \melody }
   ```
5. Use `extract_parts.py` with per-part `transposition` fields to batch-generate transposed parts.

## MIDI workflow

Use `\midi { }` inside `\score` blocks to enable MIDI output during compilation.

```lilypond
\score {
  \new Staff \melody
  \layout { }
  \midi { }
}
```

- Set `\tempo` in the `global` block or inside `\midi { \tempo 4 = 120 }`.
- Set `\set Staff.midiInstrument = "violin"` per staff for correct instrument sounds.
- Verify MIDI is generated by checking for a `.midi` file after compilation.
- If MIDI is not needed, omit the `\midi { }` block to reduce compile time.
